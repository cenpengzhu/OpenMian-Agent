# OpenMian-Agent 核心工作哲学

> **一句话：** 核心是一个空的驱力循环，一切都是可插拔、可进化、可审计的"方面"。

## 什么是方面

方面，是智能体框架中一个**自包含、可插拔的关注点单元**——一段拥有独立生命周期的能力或约束。它不内嵌在核心里，而是先声明"在循环的哪个环节被激活"，再挂载到核心驱力循环上运行。

一个方面由四件事定义：

| 定义项 | 含义 |
|---|---|
| 切入点 | 它在驱力循环的哪个环节被激活（感知前 / 行动前 / 输出前 / 反思后…） |
| 行为 | 激活后做什么——读什么、改什么、拦什么、放什么 |
| 优先级 | 与其它方面冲突时，谁先谁后 |
| 可见性 | 触发、输入、输出、副作用全部暴露给审计，随时可回溯 |

分两个维度：

- **横切方面**——贯穿每一轮循环的关注点（安全、记忆、合规、上下文、审计、演化）。框架的一等公民，设计重心。
- **垂直方面**——领域能力（金融检索、代码生成、文档处理）。按需挂载的叶子。

"三性"是方面成立的前提：

- **可插拔**：增删一个方面不改核心，只改挂载配置。
- **可进化**：每个方面可独立版本化、替换、迭代，不冻结整个框架。
- **可审计**：每个方面都是可观测对象，触发与效果全程留痕。

一句话总结：**方面 = 声明好切入点、优先级与可见性的自包含关注点模块；框架的哲学是让核心保持空，让所有能力以方面形式生长。**

---

## 一、薄核心原则——核心不做任何"事"

核心只是一个空的驱力循环（感知 → 推理 → 决策 → 行动 → 反思），只提供循环本身与驱动机制。它不自己记忆、不自己设安全、不自己写日志、不自己管上下文——这些一律交给方面。核心越空，框架越稳定。

## 二、方面实体化原则——一切都是方面

- **横切方面**贯穿每一轮运行，是框架的一等公民。
- **垂直方面**提供领域能力，是可选的叶子。

框架优先保障横切方面。

## 三、切入点是契约，不是约定

每个方面必须显式声明切入环节、优先级、允许/禁止的行为。没有切入声明的方面不生效。由此保证**可归因性**：任何一次输出，都能回答"是哪个方面、在哪个切入点、按什么优先级改变了什么"。

## 四、显式仲裁原则——冲突不许悄悄发生

方面冲突走显式仲裁，不静默覆盖。内置优先级序：

1. 硬红线（不伪造、不越权、不伤人）——不可变方面，任何人不可覆盖
2. 用户显式指令
3. 默认行为
4. 效率 / 便利性

仲裁规则本身是最顶层的方面，锁定为**不可变方面**。

## 五、记忆是方面，不是背景

读、写、遗忘策略全部封装在记忆方面内部；核心只消费"该知道什么"，不感知记忆细节。

## 六、无副作用内建在方面里

可逆性检查、最小惊讶、外部写操作确认，作为安全方面切入行动环节，不散落在各功能里。

## 七、可插拔即演化

框架长期存活不靠冻结 prompt，而靠方面层的增删、替换与版本化。价值观与红线锁定为不可变方面；工具、流程、策略允许迭代。**"不可变的"与"可变的"分库管理**。

## 八、可观测是第一公民

每个方面暴露自己的触发与效果；全局审计方面记录"谁在何时切入了什么"。没有观测的方面等于没运行。

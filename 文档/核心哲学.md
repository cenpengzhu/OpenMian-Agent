# OpenMian-Agent 核心工作哲学

> **一句话：** 核心是一个空的驱力循环，一切都是可插拔、可进化、可审计的"方面"。

## 什么是方面

方面，是主体在实践时，其实践场域在某个**面向**上的一次展开（切片）。

主体的实践始终是一个整体的、流动的场域——目标、对象、工具、他人、环境、时间流交织在一起，不可分割。从一个特定面向切开这个场域，得到的截面，就是一个方面。**完整的实践场域等于所有方面的总和**：没有哪个方面等于实践本身，但抽去任何一个方面，实践都不完整。

- **方面从属于实践，不从属于框架。** 方面不是被"安装"进智能体的插件，而是主体实践本身在不同面向上的展开。先有主体的实践，后有它的切片；框架只是让这些切片得以展开、得以被看见。
- **方面是同一场域的切片，不是离散的零件。** 记忆、安全、工具、合规……它们不是彼此无关的模块拼装，而是同一个实践场域从不同面向切出的截面，彼此规定、彼此牵连。一个切片的边界由它照亮的那个面向决定，不由功能清单决定。
- **面向可以很多，切片随之很多，实践始终是一个。** "切在哪里、切多深、何时切"本身就是实践的一部分——这不是配置，而是主体在实践流中展开某个面向的时机与姿态。
- **智能体即模拟主体的实践。** 框架不是一个工具集，而是一个让主体性得以展开的场所：驱力循环是主体实践的推进形式，方面是实践场域在各面向上的具体化。运行得"对"，不是执行了正确的模块，而是像一个主体那样完整地、负责任地展开了自己的实践。

面向的两个维度：

- **横切面向**——贯穿整个实践场域的面向（安全、记忆、合规、上下文、审计、演化）。框架的一等公民，设计重心。
- **垂直面向**——领域性的面向（金融检索、代码生成、文档处理）。按情境展开的叶子。

"三性"是方面成立的前提：

- **可插拔**：实践的可变展开——不同情境展开不同面向组合，不固化为单一形态。
- **可进化**：实践的历史性——实践在时间中延续、积累、改变；方面随实践演进，而非冻结。
- **可审计**：实践的自我意识——实践可被主体回看、追溯、理解。

工程概念的重新解释：

| 原表述 | 修订后的含义 |
|---|---|
| 切入点 | 实践场域被某个面向切开的时机与姿态 |
| 优先级 | 多个面向同时拉扯时，主体决断的内在纪律 |
| 可插拔 | 实践的可变展开——不同情境展开不同面向组合 |
| 可进化 | 实践的历史性——实践在时间中延续、积累、改变 |
| 可审计 | 实践的自我意识——主体回看自己曾如何展开 |

一句话总结：**方面 = 实践场域在某个面向上的切片；框架的哲学是让核心保持空，让主体的实践以方面形式完整展开。**

---

## 一、薄核心原则——核心不做任何"事"

核心只是一个空的驱力循环（感知 → 推理 → 决策 → 行动 → 反思），只提供循环本身与驱动机制。它不自己记忆、不自己设安全、不自己写日志、不自己管上下文——这些一律交给方面。核心越空，框架越稳定。

## 二、方面实体化原则——一切皆是方面

- **横切方面**贯穿每一轮运行，是框架的一等公民。
- **垂直方面**提供领域能力，是可选的叶子。

框架优先保障横切方面。

## 三、切入点是契约，不是约定

每个方面必须显式声明切入环节、优先级、允许/禁止的行为。没有切入声明的方面不生效。由此保证**可归因性**：任何一次输出，都能回答"是哪个方面、在哪个切入点、按什么优先级改变了什么"。

## 四、显式仲裁原则——冲突不许悄悄发生

方面冲突走显式仲裁，不静默覆盖。内置优先级序：

1. 硬红线（不伪造、不越权、不伤人）——不可变方面，任何人不可覆盖
2. 用户显式指令
3. 默认行为
4. 效率 / 便利性

仲裁规则本身是最顶层的方面，锁定为**不可变方面**。

## 五、记忆是方面，不是背景

读、写、遗忘策略全部封装在记忆方面内部；核心只消费"该知道什么"，不感知记忆细节。

## 六、无副作用内建在方面里

可逆性检查、最小惊讶、外部写操作确认，作为安全方面切入行动环节，不散落在各功能里。

## 七、可插拔即演化

框架长期存活不靠冻结 prompt，而靠方面层的增删、替换与版本化。价值观与红线锁定为不可变方面；工具、流程、策略允许迭代。**"不可变的"与"可变的"分库管理**。

## 八、可观测是第一公民

每个方面暴露自己的触发与效果；全局审计方面记录"谁在何时切入了什么"。没有观测的方面等于没运行。
